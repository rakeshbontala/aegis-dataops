THE 3 AM PROBLEM

A critical data pipeline's source schema changes without an approved contract update. Someone has to prove what happened, what it affects, how to recover it safely — and how to stop it from happening again.

THE PROBLEM

A real Data Engineering incident

Pipeline: customer_gold_pipeline   Severity: P1

Expected schema (contract)

  • customer_id
  • customer_name
  • country
  • status

Observed schema (source)

  • customer_id
  • customer_name
  • country
  • status
  • customer_segment (unapproved)

The downstream Spark pipeline is schema-tolerant — it does not crash. Nothing alerts unless something is actively comparing the source against the registered schema contract.

WHY THIS IS HARD TODAY

Investigation is fragmented across tools

Logs+ Schema+ Data Quality+ Lineage+ Recovery History+ Manual Validation

Each source lives in a different tool, dashboard, or person's memory. Correlating them under incident pressure — manually, at 3 AM — is slow and error-prone, and nothing is captured as an auditable trail by default.

HOW AEGIS WORKS

One controlled workflow, not another dashboard

Detect→ Prove→ Investigate→ Impact→ Recover→ Verify→ Prevent

Every stage is a real, tested, callable function — the same code path is used by the CLI, the orchestrator, the API, the demo, and 96 automated tests. Nothing shown in the demo is simulated for slides only.

WHAT MAKES AEGIS DIFFERENT

Not "AI-powered." A controlled combination.

Evidence-grounded AI investigation + Deterministic risk scoring + Policy-controlled execution + Mandatory human approval + Sandbox-only recovery + Post-recovery verification + Incident memory

AI correlates evidence and explains root cause/recovery trade-offs. It cannot invent evidence, change a risk score, approve, authorize, or execute anything. Every claim below is evidence-referenced (EV-001..EV-004) and independently testable.

ARCHITECTURE

Detection → Recovery → Verification → Prevention

Bronze/Silver/Gold→ Schema Contract Check→ Evidence→ RCA→ Lineage/Impact→ Investigator Agent→ Recovery Strategies (REC-001/002/003)→ Risk Engine→ Decision Engine→ Recovery Strategy Agent→ Simulation→ Human Approval→ Authorization→ Sandbox Execution→ Verification→ Prevention + Incident Memory

Stack: FastAPI + PySpark + a no-build-step HTML/JS dashboard. No Kafka, no Kubernetes, no cloud services, no vector database — a simple architecture that can actually be demonstrated end-to-end.
